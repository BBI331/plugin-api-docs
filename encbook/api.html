ENCBOOK

도감 API 문서

다른 플러그인·스크립트에서 도감을 조회·조작하고, 도감 이벤트에 반응하는 콘텐츠를 만들 수 있습니다.

목차 시작하기 용어 조회 도감 전체 조회 카탈로그 조작 이벤트 규칙
메인 페이지로 이동

시작하기

Skript (skript-reflect)

import:
    kr.bibi.encbook.api.EncbookProvider

set {_api} to EncbookProvider.get()

# 1번 카테고리 · 1페이지 · 5번 도감 슬롯의 해금 여부 확인
if {_api}.isUnlocked(player's uuid, 1, 1, 5) is true:
    send "이미 해금한 도감 슬롯입니다"

Java

encbook.jar 를 프로젝트에 compileOnly 로 추가하고, plugin.yml 에 softdepend: [EncBook2] 를 넣으세요.

EncbookAPI api = EncbookProvider.get();

// 숫자 3개로 바로 쓰거나, SlotRef 로 묶어 써도 같은 의미
boolean done = api.isUnlocked(uuid, 1, 1, 5);
boolean same = api.isUnlocked(uuid, SlotRef.of(1, 1, 5));

용어

아래 메소드 설명에서 반복해서 쓰는 표현들입니다.

uuid대상 플레이어를 식별하는 고유 값입니다. Skript 에서는 player's uuid 로 얻습니다.
카테고리도감의 카테고리 번호를 의미하며, 위에서 아래 순서대로 1 ~ 5번입니다. (기본값 기준 1번 '블럭' · 2번 '광물' · 3번 '작물' · 4번 '물고기' · 5번 '기타')
페이지그 카테고리 안에서 몇 번째 페이지인지를 의미하며, 1번부터 시작합니다. 페이지 수는 카테고리마다 config 에서 정하며 기본값은 5입니다.
슬롯그 페이지 안에서 몇 번째 도감 슬롯인지를 의미하며, 왼쪽 위부터 오른쪽 방향으로 1 ~ 30번까지 매겨집니다.
진행률해금을 마친 비율을 0.0 ~ 100.0 사이의 숫자(%)로 나타냅니다.
도감 슬롯 하나는 카테고리 · 페이지 · 슬롯 세 숫자로 지정합니다. 예를 들어 (1, 2, 5) 는 1번 카테고리의 2페이지 5번 도감 슬롯입니다.
Java 에서는 세 숫자를 SlotRef.of(1, 2, 5) 한 덩어리로 묶어 쓸 수도 있습니다 (같은 의미).

조회

플레이어의 도감 진행 상황을 확인합니다. 접속 중이든 오프라인이든 동일하게 사용합니다.

isUnlocked(uuid, 카테고리, 페이지, 슬롯)→ true / false

플레이어가 해당 도감 슬롯을 해금하였는지 여부를 반환합니다.

unlockedAt(uuid, 카테고리, 페이지, 슬롯)→ 해금 시각

플레이어가 해당 도감 슬롯을 해금한 시각을 반환합니다. 아직 해금하지 않았다면 빈 값을 반환합니다.

unlockedCount(uuid)→ 숫자

플레이어가 지금까지 해금한 도감 슬롯의 총 개수를 반환합니다.

unlockedCount(uuid, 카테고리)→ 숫자

플레이어가 해당 카테고리에서 해금한 도감 슬롯 개수를 반환합니다.

totalProgress(uuid)→ 진행률

플레이어의 도감 전체 진행률을 0.0 ~ 100.0 사이의 값으로 반환합니다.

categoryProgress(uuid, 카테고리)→ 진행률

플레이어의 해당 카테고리 진행률을 0.0 ~ 100.0 사이의 값으로 반환합니다.

isCategoryComplete(uuid, 카테고리)→ true / false

플레이어가 해당 카테고리를 100% 완성했는지 여부를 반환합니다.

hasClaimedCategoryReward(uuid, 카테고리)→ true / false

플레이어가 해당 카테고리의 완료 보상을 수령하였는지 여부를 반환합니다.

hasClaimedProgressReward(uuid, 단계)→ true / false

플레이어가 해당 진척도 단계의 보상을 수령하였는지 여부를 반환합니다.

claimableProgressRewards(uuid)→ 단계 목록

플레이어가 달성했지만 아직 수령하지 않은 진척도 보상 단계 목록을 반환합니다.

# 예시 : 진행률 확인 명령어
command /내도감:
    trigger:
        set {_api} to EncbookProvider.get()
        send "전체 진행률: %{_api}.totalProgress(player's uuid)%%%"
        send "카테고리 1: %{_api}.categoryProgress(player's uuid, 1)%%%"

도감 전체 조회

플레이어의 도감 데이터를 한 번에 받아 여러 값을 연속으로 확인할 때 사용합니다.

loadBook(uuid)→ PlayerBook (비동기)

플레이어의 도감 데이터를 PlayerBook 객체 하나로 반환합니다. 이 객체에서 해금 여부·진행률·보상 수령 여부를 모두 확인할 수 있습니다.

도감 기록이 전혀 없는 플레이어는 빈 값을 반환합니다.

언제 사용하나요?
위 조회 메소드는 호출할 때마다 데이터를 한 번씩 읽습니다. 한 플레이어의 값을 여러 개 확인하거나 많은 인원을 반복문으로 처리할 때는, 이 메소드로 데이터를 한 번만 읽어 두고 그 객체에서 값을 꺼내는 편이 빠릅니다.
확인할 값이 한두 개뿐이라면 위 조회 메소드를 그대로 쓰면 됩니다. 
// Java : 도감 데이터를 한 번 받아 여러 값을 확인
api.loadBook(uuid).thenAccept(book -> book.ifPresent(b -> {
    log.info("전체 진행률 " + b.totalProgress() + "%");
    log.info("해금 슬롯 " + b.unlockedCount() + "개");
    log.info("1-1-5 해금 여부 " + b.isUnlocked(1, 1, 5));
}));

카탈로그

관리자가 /도감 설정 에서 각 도감 슬롯에 지정해 둔 수집 목표 아이템 목록을 조회합니다. 플레이어의 해금 현황은 위의 조회 섹션에서 확인합니다.

slotAt(카테고리, 페이지, 슬롯)→ CatalogSlot

관리자가 해당 도감 슬롯에 지정한 목표 아이템을 반환합니다.
목표 아이템이 지정되지 않은 빈 슬롯이면 빈 값을 반환합니다.

.item() 으로 목표 아이템을, .requiredAmount() 로 해금에 필요한 개수를 꺼냅니다

findSlot(아이템)→ SlotRef

해당 아이템이 어느 도감 슬롯에 목표로 지정되어 있는지 반환합니다.
목표로 지정된 아이템이 아니면 빈 값을 반환합니다.

반환된 값에서 .category() · .page() · .slot() 으로 각 번호를 꺼냅니다

totalSlots()→ 숫자

지정된 목표 아이템의 총 개수를 반환합니다. (설정된 슬롯 하나당 1개로 계산)

totalSlots(카테고리)→ 숫자

해당 카테고리에서 목표 아이템이 지정된 도감 슬롯의 개수를 반환합니다.

조작

도감 슬롯을 해금·잠금하거나 도감 화면을 엽니다. 해금 시 이벤트가 발생하며 취소될 수 있습니다.

unlock(uuid, 카테고리, 페이지, 슬롯)→ 결과

지정한 도감 슬롯을 조용히 해금하고 처리 결과를 반환합니다. 보상·알림·효과음 없이 처리되며, 데이터 보정용으로 사용합니다.

대상이 오프라인이면 비동기로 처리를 시작하고 PENDING 을 반환합니다

unlockWithReward(uuid, 카테고리, 페이지, 슬롯)→ 결과

지정한 도감 슬롯을 플레이어가 직접 해금한 것처럼 처리하고 결과를 반환합니다. 해금 보상 지급과 알림이 함께 이루어지며, 퀘스트·이벤트 연동에 적합합니다. 아이템은 소모하지 않습니다.

lock(uuid, 카테고리, 페이지, 슬롯)→ 결과

지정한 도감 슬롯의 해금을 취소하고 결과를 반환합니다. 이미 지급된 보상은 회수하지 않습니다.

unlockAsync(uuid, 슬롯, 보상여부)→ 결과 (비동기)

지정한 도감 슬롯을 해금하고, 확정된 처리 결과를 비동기로 반환합니다.

언제 사용하나요? 위 unlock 은 오프라인 대상에게 PENDING 을 돌려주므로 실제로 해금됐는지, 이미 해금 상태였는지 알 수 없습니다. 처리 결과에 따라 다음 동작이 달라질 때 (예: 중복 지급 방지, 성공 여부 안내·기록) 이 메소드를 사용하면 확정된 결과를 받을 수 있습니다.

openBook(플레이어, uuid, 모드, 카테고리, 페이지)

지정한 플레이어에게 해당 도감 화면을 열어줍니다.

반환되는 결과값 UnlockResult 의 종류 : SUCCESS(처리 완료) · ALREADY_UNLOCKED(이미 해금됨) · EMPTY_SLOT(카탈로그에 목표가 없는 빈 슬롯) · PLAYER_NOT_FOUND(대상 데이터 없음) · CANCELLED(이벤트에서 취소됨) · PENDING(오프라인 대상이라 비동기로 처리 시작) 

# 예시 : 퀘스트 완료 시 특정 도감 슬롯을 보상과 함께 해금
{_api}.unlockWithReward(player's uuid, 1, 1, 5)

이벤트

패키지 kr.bibi.encbook.api.event 안에 있으며, import 한 클래스 이름을 그대로 on ...: 에 씁니다. 아래 메소드에 마우스를 올리면 무엇을 돌려주는지 볼 수 있습니다.

EncbookUnlockEvent취소 가능

도감 슬롯 해금
도감 슬롯이 해금되기 직전에 발생합니다. 직접 등록·깃펜·관리자·API 등 모든 경로에서 공통으로 발생하며, 취소하면 해금되지 않고 아이템·깃펜도 소모되지 않습니다.

getPlayer()¹ · getPlayerId() · getCategory() · getPage() · getSlot() · getSlotRef() · getCause()²

EncbookFeatherUseEvent취소 가능

비비의 깃펜 사용
잠긴 도감 슬롯에 깃펜을 사용하는 순간 발생합니다. 취소하면 깃펜이 소모되지 않고 해금도 이루어지지 않습니다. 취소하지 않으면 이어서 EncbookUnlockEvent(FEATHER) 가 발생합니다.

getPlayer() · getCategory() · getPage() · getSlot() · getSlotRef()

EncbookCategoryCompleteEvent취소 불가

카테고리 완성
카테고리 진행도가 100% 에 도달한 순간 발생합니다. 이미 확정된 해금의 결과이므로 취소할 수 없습니다. 막으려면 EncbookUnlockEvent 를 취소하세요.

getPlayer()¹ · getPlayerId() · getCategory()

EncbookCategoryRewardClaimEvent취소 가능

카테고리 완료 보상 수령
카테고리 완료 보상을 지급하기 직전에 발생합니다. 취소하면 지급되지 않으며, getRewards() 로 받은 목록을 수정하면 그 내용대로 지급됩니다.

getPlayer() · getCategory() · getRewards()

EncbookProgressRewardClaimEvent취소 가능

진척도 보상 수령
진척도 보상을 지급하기 직전에 발생합니다. 취소하면 지급되지 않으며, getRewards() 로 받은 목록을 수정하면 그 내용대로 지급됩니다.

getPlayer() · getLevel() · getRewards()

EncbookOpenEvent취소 가능

도감 열기
도감 화면이 열리기 직전에 발생합니다. 취소하면 화면이 열리지 않습니다.

getViewer() · getOwner() · getMode() · getCategory() · getPage()

EncbookResetEvent취소 가능

도감 초기화
플레이어의 도감 기록이 초기화되기 직전에 발생합니다. 취소하면 초기화되지 않습니다.

getPlayer()¹ · getTargetId()

EncbookReloadEvent취소 불가

설정 리로드
/도감 리로드 로 설정과 카탈로그를 다시 불러온 직후 발생합니다. 이미 끝난 작업에 대한 통지이므로 취소할 수 없습니다.

¹ 접속 중인 대상만 돌려줍니다. 관리자·API 가 오프라인 대상을 조작한 경우 null 이므로 getPlayerId 를 사용하세요.
² 등록 경로: PLAYER_REGISTER(직접) · FEATHER(깃펜) · ADMIN(관리자) · API 

# 예시 : 해금 알림 + 특정 월드 해금 금지
import:
    kr.bibi.encbook.api.event.EncbookUnlockEvent

on EncbookUnlockEvent:
    set {_p} to event.getPlayer()
    if {_p} is set:
        if world of {_p} is "event_world":
            event.setCancelled(true)
            send "&c이 월드에서는 도감을 사용할 수 없습니다" to {_p}
            stop
        send "도감 등록! (카테고리 %event.getCategory()% · 슬롯 %event.getSlot()%)" to {_p}

규칙

  • 조회 메소드는 접속 여부를 신경 쓸 필요가 없습니다. 접속 중이면 메모리에서 즉시, 오프라인이면 데이터베이스에서 읽어 답합니다(읽은 도감은 몇 초간 재사용). 다만 오프라인 조회는 데이터베이스를 거치므로, 수십 명을 반복문으로 훑을 때는 loadBook 으로 도감을 한 번에 받아 쓰는 편이 효율적입니다.
  • 해금·잠금 메소드를 오프라인 대상에 부르면 비동기로 처리를 시작하고 PENDING 을 반환합니다. 확정된 결과가 필요하면 unlockAsync 를 사용하세요.
  • openBook 은 메인 스레드가 아니면 자동으로 다음 틱에 예약됩니다.
  • 공개 API(kr.bibi.encbook.api)의 이름은 버전이 올라가도 유지됩니다.
