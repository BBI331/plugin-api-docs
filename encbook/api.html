시작하기Getting Started

Skript (skript-reflect)

import:
    kr.bibi.encbook.api.EncbookProvider

set {_api} to EncbookProvider.get()

# 1번 카테고리 · 1페이지 · 5번 도감 슬롯의 해금 여부 확인
if {_api}.isUnlocked(player's uuid, 1, 1, 5) is true:
    send "이미 해금한 도감 슬롯입니다"
import:
    kr.bibi.encbook.api.EncbookProvider

set {_api} to EncbookProvider.get()

# Check whether category 1 · page 1 · slot 5 is unlocked
if {_api}.isUnlocked(player's uuid, 1, 1, 5) is true:
    send "You already unlocked this encyclopedia slot"

encbook.jar 를 프로젝트에 compileOnly 로 추가하고, plugin.yml 에 softdepend: [EncBook] 를 넣으세요.Add encbook.jar to your project as compileOnly, and put softdepend: [EncBook] in your plugin.yml.

EncbookAPI api = EncbookProvider.get();

// 숫자 3개로 바로 쓰거나, SlotRef 로 묶어 써도 같은 의미

용어Terminology

아래 메소드 설명에서 반복해서 쓰는 표현들입니다.Terms used repeatedly in the method descriptions below.

uuid대상 플레이어를 식별하는 고유 값입니다. Skript 에서는 player's uuid 로 얻습니다.
카테고리도감의 카테고리 번호를 의미하며, 위에서 아래 순서대로 1 ~ 5번입니다. (기본값 기준 1번 '블럭' · 2번 '광물' · 3번 '작물' · 4번 '물고기' · 5번 '기타')
페이지그 카테고리 안에서 몇 번째 페이지인지를 의미하며, 1번부터 시작합니다. 페이지 수는 카테고리마다 config 에서 정하며 기본값은 5입니다.
슬롯그 페이지 안에서 몇 번째 도감 슬롯인지를 의미하며, 왼쪽 위부터 오른쪽 방향으로 1 ~ 30번까지 매겨집니다.
진행률해금을 마친 비율을 0.0 ~ 100.0 사이의 숫자(%)로 나타냅니다.
uuidA unique value identifying the target player. In Skript, get it with player's uuid.
categoryThe encyclopedia category number, 1 – 5 from top to bottom. (With default settings: 1 'Blocks' · 2 'Ores' · 3 'Crops' · 4 'Fish' · 5 'Misc')
pageThe page number within that category, starting from 1. The page count is set per category in the config; the default is 5.
slotThe slot number within that page, numbered 1 – 30 from the top-left going right.
progressThe unlocked ratio, as a number (%) between 0.0 and 100.0.
도감 슬롯 하나는 카테고리 · 페이지 · 슬롯 세 숫자로 지정합니다. 예를 들어 (1, 2, 5) 는 1번 카테고리의 2페이지 5번 도감 슬롯입니다.
Java 에서는 세 숫자를 SlotRef.of(1, 2, 5) 한 덩어리로 묶어 쓸 수도 있습니다 (같은 의미).
A single encyclopedia slot is addressed by three numbers: category · page · slot. For example, (1, 2, 5) is slot 5 on page 2 of category 1.
In Java you can also bundle the three numbers into one SlotRef.of(1, 2, 5) (same meaning).

조회Queries

플레이어의 도감 진행 상황을 확인합니다. 접속 중이든 오프라인이든 동일하게 사용합니다.Check a player's encyclopedia progress. Works the same whether the player is online or offline.

isUnlocked(uuid, 카테고리category, 페이지page, 슬롯slot)→ true / false

플레이어가 해당 도감 슬롯을 해금하였는지 여부를 반환합니다.Returns whether the player has unlocked that encyclopedia slot.

unlockedAt(uuid, 카테고리category, 페이지page, 슬롯slot)→ 해금 시각unlock time

플레이어가 해당 도감 슬롯을 해금한 시각을 반환합니다. 아직 해금하지 않았다면 빈 값을 반환합니다.Returns when the player unlocked that slot. Returns empty if it is not unlocked yet.

unlockedCount(uuid)→ 숫자number

플레이어가 지금까지 해금한 도감 슬롯의 총 개수를 반환합니다.Returns the total number of encyclopedia slots the player has unlocked so far.

unlockedCount(uuid, 카테고리category)→ 숫자number

플레이어가 해당 카테고리에서 해금한 도감 슬롯 개수를 반환합니다.Returns the number of slots the player has unlocked in that category.

totalProgress(uuid)→ 진행률progress

플레이어의 도감 전체 진행률을 0.0 ~ 100.0 사이의 값으로 반환합니다.Returns the player's overall encyclopedia progress as a value between 0.0 and 100.0.

categoryProgress(uuid, 카테고리category)→ 진행률progress

플레이어의 해당 카테고리 진행률을 0.0 ~ 100.0 사이의 값으로 반환합니다.Returns the player's progress in that category as a value between 0.0 and 100.0.

isCategoryComplete(uuid, 카테고리category)→ true / false

플레이어가 해당 카테고리를 100% 완성했는지 여부를 반환합니다.Returns whether the player has completed that category 100%.

hasClaimedCategoryReward(uuid, 카테고리category)→ true / false

플레이어가 해당 카테고리의 완료 보상을 수령하였는지 여부를 반환합니다.Returns whether the player has claimed that category's completion reward.

hasClaimedProgressReward(uuid, 단계level)→ true / false

플레이어가 해당 진척도 단계의 보상을 수령하였는지 여부를 반환합니다.Returns whether the player has claimed the reward for that progress milestone level.

claimableProgressRewards(uuid)→ 단계 목록level list

플레이어가 달성했지만 아직 수령하지 않은 진척도 보상 단계 목록을 반환합니다.Returns the list of milestone levels the player has reached but not yet claimed.

# 예시 : 진행률 확인 명령어
command /내도감:
    trigger:
        set {_api} to EncbookProvider.get()
        send "전체 진행률: %{_api}.totalProgress(player's uuid)%%%"
        send "카테고리 1: %{_api}.categoryProgress(player's uuid, 1)%%%"
# Example: a progress-check command
command /mybook:
    trigger:
        set {_api} to EncbookProvider.get()
        send "Total progress: %{_api}.totalProgress(player's uuid)%%%"
        send "Category 1: %{_api}.categoryProgress(player's uuid, 1)%%%"

도감 전체 조회Loading the Whole Book

플레이어의 도감 데이터를 한 번에 받아 여러 값을 연속으로 확인할 때 사용합니다.Load a player's encyclopedia data once, then check many values in a row.

loadBook(uuid)→ PlayerBook (비동기)(async)

플레이어의 도감 데이터를 PlayerBook 객체 하나로 반환합니다. 이 객체에서 해금 여부·진행률·보상 수령 여부를 모두 확인할 수 있습니다.Returns the player's encyclopedia data as a single PlayerBook object. From it you can read unlock states, progress, and reward-claim states.

도감 기록이 전혀 없는 플레이어는 빈 값을 반환합니다.Returns empty for players with no encyclopedia records at all.

언제 사용하나요?
위 조회 메소드는 호출할 때마다 데이터를 한 번씩 읽습니다. 한 플레이어의 값을 여러 개 확인하거나 많은 인원을 반복문으로 처리할 때는, 이 메소드로 데이터를 한 번만 읽어 두고 그 객체에서 값을 꺼내는 편이 빠릅니다.
확인할 값이 한두 개뿐이라면 위 조회 메소드를 그대로 쓰면 됩니다.
When should I use this?
Each query method above reads the data once per call. When checking several values for one player, or looping over many players, it is faster to read the data once with this method and pull values from the object.
If you only need one or two values, just use the query methods above. 
// Java : 도감 데이터를 한 번 받아 여러 값을 확인
api.loadBook(uuid).thenAccept(book -> book.ifPresent(b -> {
    log.info("전체 진행률 " + b.totalProgress() + "%");
    log.info("해금 슬롯 " + b.unlockedCount() + "개");
    log.info("1-1-5 해금 여부 " + b.isUnlocked(1, 1, 5));
}));
// Java: load the book once and check several values
api.loadBook(uuid).thenAccept(book -> book.ifPresent(b -> {
    log.info("total progress " + b.totalProgress() + "%");
    log.info("unlocked slots " + b.unlockedCount());
    log.info("1-1-5 unlocked " + b.isUnlocked(1, 1, 5));
}));

카탈로그Catalog

관리자가 /도감 설정 에서 각 도감 슬롯에 지정해 둔 수집 목표 아이템 목록을 조회합니다. 플레이어의 해금 현황은 위의 조회 섹션에서 확인합니다.Look up the collection-target items that admins assigned to each encyclopedia slot in /도감 설정 (settings screen). Per-player unlock states are covered in the Queries section above.

slotAt(카테고리category, 페이지page, 슬롯slot)→ CatalogSlot

관리자가 해당 도감 슬롯에 지정한 목표 아이템을 반환합니다.
목표 아이템이 지정되지 않은 빈 슬롯이면 빈 값을 반환합니다.Returns the target item an admin assigned to that encyclopedia slot.
Returns empty for blank slots with no target item assigned.

.item() 으로 목표 아이템을, .requiredAmount() 로 해금에 필요한 개수를 꺼냅니다Use .item() for the target item and .requiredAmount() for the amount required to unlock

findSlot(아이템item)→ SlotRef

해당 아이템이 어느 도감 슬롯에 목표로 지정되어 있는지 반환합니다.
목표로 지정된 아이템이 아니면 빈 값을 반환합니다.Returns which encyclopedia slot has that item as its target.
Returns empty if the item is not the target of any slot.

반환된 값에서 .category() · .page() · .slot() 으로 각 번호를 꺼냅니다From the returned value, read each number with .category() · .page() · .slot()

totalSlots()→ 숫자number

지정된 목표 아이템의 총 개수를 반환합니다. (설정된 슬롯 하나당 1개로 계산)Returns the total number of assigned target items. (Each configured slot counts as 1)

totalSlots(카테고리category)→ 숫자number

해당 카테고리에서 목표 아이템이 지정된 도감 슬롯의 개수를 반환합니다.Returns the number of slots with a target item assigned in that category.

조작Actions

도감 슬롯을 해금·잠금하거나 도감 화면을 엽니다. 해금 시 이벤트가 발생하며 취소될 수 있습니다.Unlock or lock encyclopedia slots, or open the encyclopedia screen. Unlocking fires an event and can be cancelled.

unlock(uuid, 카테고리category, 페이지page, 슬롯slot)→ 결과result

지정한 도감 슬롯을 조용히 해금하고 처리 결과를 반환합니다. 보상·알림·효과음 없이 처리되며, 데이터 보정용으로 사용합니다.Silently unlocks the given slot and returns the result. No rewards, notifications, or sounds — intended for data fixes.

대상이 오프라인이면 비동기로 처리를 시작하고 PENDING 을 반환합니다If the target is offline, processing starts asynchronously and PENDING is returned

unlockWithReward(uuid, 카테고리category, 페이지page, 슬롯slot)→ 결과result

지정한 도감 슬롯을 플레이어가 직접 해금한 것처럼 처리하고 결과를 반환합니다. 해금 보상 지급과 알림이 함께 이루어지며, 퀘스트·이벤트 연동에 적합합니다. 아이템은 소모하지 않습니다.Unlocks the given slot as if the player did it themselves, and returns the result. Unlock rewards and notifications are included — a good fit for quest/event integrations. No items are consumed.

lock(uuid, 카테고리category, 페이지page, 슬롯slot)→ 결과result

지정한 도감 슬롯의 해금을 취소하고 결과를 반환합니다. 이미 지급된 보상은 회수하지 않습니다.Re-locks the given slot and returns the result. Rewards already granted are not taken back.

unlockAsync(uuid, 슬롯slot, 보상여부withReward)→ 결과 (비동기)result (async)

지정한 도감 슬롯을 해금하고, 확정된 처리 결과를 비동기로 반환합니다.Unlocks the given slot and returns the confirmed result asynchronously.

언제 사용하나요? 위 unlock 은 오프라인 대상에게 PENDING 을 돌려주므로 실제로 해금됐는지, 이미 해금 상태였는지 알 수 없습니다. 처리 결과에 따라 다음 동작이 달라질 때 (예: 중복 지급 방지, 성공 여부 안내·기록) 이 메소드를 사용하면 확정된 결과를 받을 수 있습니다.When should I use this? unlock above returns PENDING for offline targets, so you cannot tell whether the slot was actually unlocked or already unlocked. When your next step depends on the outcome (e.g. preventing duplicate rewards, reporting or recording success), use this method to get a confirmed result.

openBook(플레이어player, uuid, 모드mode, 카테고리category, 페이지page)

지정한 플레이어에게 해당 도감 화면을 열어줍니다.Opens the encyclopedia screen for the given player.

반환되는 결과값 UnlockResult 의 종류 : SUCCESS(처리 완료) · ALREADY_UNLOCKED(이미 해금됨) · EMPTY_SLOT(카탈로그에 목표가 없는 빈 슬롯) · PLAYER_NOT_FOUND(대상 데이터 없음) · CANCELLED(이벤트에서 취소됨) · PENDING(오프라인 대상이라 비동기로 처리 시작)Possible UnlockResult values: SUCCESS (done) · ALREADY_UNLOCKED · EMPTY_SLOT (no target in the catalog) · PLAYER_NOT_FOUND (no data for the target) · CANCELLED (cancelled by an event) · PENDING (offline target — async processing started) 

# 예시 : 퀘스트 완료 시 특정 도감 슬롯을 보상과 함께 해금
{_api}.unlockWithReward(player's uuid, 1, 1, 5)
# Example: unlock a specific slot with rewards when a quest completes
{_api}.unlockWithReward(player's uuid, 1, 1, 5)

이벤트Events

패키지 kr.bibi.encbook.api.event 안에 있으며, import 한 클래스 이름을 그대로 on ...: 에 씁니다. 아래 메소드에 마우스를 올리면 무엇을 돌려주는지 볼 수 있습니다.These live in the kr.bibi.encbook.api.event package; use the imported class name directly in on ...:. Hover over the methods below to see what each one returns.

EncbookUnlockEvent취소 가능Cancellable

도감 슬롯 해금Slot unlock
도감 슬롯이 해금되기 직전에 발생합니다. 직접 등록·깃펜·관리자·API 등 모든 경로에서 공통으로 발생하며, 취소하면 해금되지 않고 아이템·깃펜도 소모되지 않습니다.Fires just before an encyclopedia slot is unlocked. Fires on every path — direct registration, quill, admin, API — and cancelling prevents the unlock without consuming any items or quills.

getPlayer()¹ · getPlayerId() · getCategory() · getPage() · getSlot() · getSlotRef() · getCause()²

EncbookFeatherUseEvent취소 가능Cancellable

비비의 깃펜 사용BIBI's Quill use
잠긴 도감 슬롯에 깃펜을 사용하는 순간 발생합니다. 취소하면 깃펜이 소모되지 않고 해금도 이루어지지 않습니다. 취소하지 않으면 이어서 EncbookUnlockEvent(FEATHER) 가 발생합니다. config 에서 비비의 깃펜 사용 가능 여부 를 false 로 설정한 카테고리는 깃펜 사용 자체가 거부되므로 이 이벤트도 발생하지 않습니다.Fires the moment a quill is used on a locked slot. Cancelling consumes no quill and performs no unlock. If not cancelled, EncbookUnlockEvent(FEATHER) fires next. In categories where the config option 비비의 깃펜 사용 가능 여부 (quill allowed) is set to false, quill use itself is rejected, so this event does not fire either.

getPlayer() · getCategory() · getPage() · getSlot() · getSlotRef()

EncbookCategoryCompleteEvent취소 불가Not cancellable

카테고리 완성Category complete
카테고리 진행도가 100% 에 도달한 순간 발생합니다. 이미 확정된 해금의 결과이므로 취소할 수 없습니다. 막으려면 EncbookUnlockEvent 를 취소하세요.Fires the moment a category's progress reaches 100%. It is the result of an already-confirmed unlock, so it cannot be cancelled. To prevent it, cancel EncbookUnlockEvent instead.

getPlayer()¹ · getPlayerId() · getCategory()

EncbookCategoryRewardClaimEvent취소 가능Cancellable

카테고리 완료 보상 수령Category reward claim
카테고리 완료 보상을 지급하기 직전에 발생합니다. 취소하면 지급되지 않으며, getRewards() 로 받은 목록을 수정하면 그 내용대로 지급됩니다.Fires just before a category completion reward is paid out. Cancelling prevents the payout, and edits to the list from getRewards() are paid out as-is.

getPlayer() · getCategory() · getRewards()

EncbookProgressRewardClaimEvent취소 가능Cancellable

진척도 보상 수령Progress reward claim
진척도 보상을 지급하기 직전에 발생합니다. 취소하면 지급되지 않으며, getRewards() 로 받은 목록을 수정하면 그 내용대로 지급됩니다.Fires just before a progress milestone reward is paid out. Cancelling prevents the payout, and edits to the list from getRewards() are paid out as-is.

getPlayer() · getLevel() · getRewards()

EncbookOpenEvent취소 가능Cancellable

도감 열기Encyclopedia open
도감 화면이 열리기 직전에 발생합니다. 취소하면 화면이 열리지 않습니다.Fires just before the encyclopedia screen opens. Cancelling keeps it closed.

getViewer() · getOwner() · getMode() · getCategory() · getPage()

EncbookResetEvent취소 가능Cancellable

도감 초기화Encyclopedia reset
플레이어의 도감 기록이 초기화되기 직전에 발생합니다. 취소하면 초기화되지 않습니다.Fires just before a player's encyclopedia records are reset. Cancelling prevents the reset.

getPlayer()¹ · getTargetId()

EncbookReloadEvent취소 불가Not cancellable

설정 리로드Config reload
/도감 리로드 로 설정과 카탈로그를 다시 불러온 직후 발생합니다. 이미 끝난 작업에 대한 통지이므로 취소할 수 없습니다.Fires right after settings and the catalog are reloaded via /도감 리로드 (reload command). It is a notification of already-finished work and cannot be cancelled.

¹ 접속 중인 대상만 돌려줍니다. 관리자·API 가 오프라인 대상을 조작한 경우 null 이므로 getPlayerId 를 사용하세요.
² 등록 경로: PLAYER_REGISTER(직접) · FEATHER(깃펜) · ADMIN(관리자) · API¹ Returns online targets only. When an admin or the API acts on an offline target this is null — use getPlayerId instead.
² Registration paths: PLAYER_REGISTER (direct) · FEATHER (quill) · ADMIN · API 

# 예시 : 해금 알림 + 특정 월드 해금 금지
import:
    kr.bibi.encbook.api.event.EncbookUnlockEvent

on EncbookUnlockEvent:
    set {_p} to event.getPlayer()
    if {_p} is set:
        if world of {_p} is "event_world":
            event.setCancelled(true)
            send "&c이 월드에서는 도감을 사용할 수 없습니다" to {_p}
            stop
        send "도감 등록! (카테고리 %event.getCategory()% · 슬롯 %event.getSlot()%)" to {_p}
# Example: unlock notification + block unlocks in a specific world
import:
    kr.bibi.encbook.api.event.EncbookUnlockEvent

on EncbookUnlockEvent:
    set {_p} to event.getPlayer()
    if {_p} is set:
        if world of {_p} is "event_world":
            event.setCancelled(true)
            send "&cThe encyclopedia cannot be used in this world" to {_p}
            stop
        send "Registered! (category %event.getCategory()% · slot %event.getSlot()%)" to {_p}

규칙Rules

  • 조회 메소드는 접속 여부를 신경 쓸 필요가 없습니다. 접속 중이면 메모리에서 즉시, 오프라인이면 데이터베이스에서 읽어 답합니다(읽은 도감은 몇 초간 재사용). 다만 오프라인 조회는 데이터베이스를 거치므로, 수십 명을 반복문으로 훑을 때는 loadBook 으로 도감을 한 번에 받아 쓰는 편이 효율적입니다.
  • 해금·잠금 메소드를 오프라인 대상에 부르면 비동기로 처리를 시작하고 PENDING 을 반환합니다. 확정된 결과가 필요하면 unlockAsync 를 사용하세요.
  • openBook 은 메인 스레드가 아니면 자동으로 다음 틱에 예약됩니다.
  • 공개 API(kr.bibi.encbook.api)의 이름은 버전이 올라가도 유지됩니다.
  • Query methods don't care whether the player is online. Online players answer instantly from memory; offline players are read from the database (a loaded book is reused for a few seconds). Offline queries do go through the database though, so when looping over dozens of players, it is more efficient to load each book once with loadBook.
  • Calling unlock/lock methods on an offline target starts async processing and returns PENDING. Use unlockAsync when you need a confirmed result.
  • openBook is automatically scheduled for the next tick when called off the main thread.
  • Names in the public API (kr.bibi.encbook.api) stay stable across versions.
